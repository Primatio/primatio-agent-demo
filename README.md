# Primatio Vault Agent Demo

Public reference client demonstrating the **Primatio Vault Zero-Knowledge Agent Protocol** end-to-end with **Playwright** browser automation.

This repository shows how an AI agent or automation script can authenticate to a website using credentials stored in Primatio Vault **without ever storing static passwords, receiving plaintext secrets from the backend, or bypassing biometric approval**.

## Security Guarantees

- **Zero-Knowledge Transport:** The Primatio backend never sees plaintext credentials. The Vault mobile app seals the credential locally using **HPKE Base Mode (`DHKEM(X25519, HKDF-SHA256)` + `HKDF-SHA256` + `AES-256-GCM`)** to an ephemeral public key generated by this process.
- **DPoP Proof-of-Possession (RFC 9449):** Every OAuth and API request is bound to an ephemeral **ES256 (P-256)** keypair generated locally.
- **Cryptographic Key Binding (`vault-hpke-bind+jwt`):** The ephemeral X25519 key is signed with the DPoP key and verified on the user's phone before sealing.
- **Human-in-the-Loop Biometrics + Number Matching:** Every credential release requires explicit biometric approval and matching a 2-digit `match_code` in the Primatio Vault mobile app.
- **No Secret Logging:** Decrypted credentials stay strictly in memory inside the local process, are passed directly to Playwright's `page.fill()`, and are cleared in a `finally` block.

## Prerequisites

1. **Node.js >= 22** (tested with Node 24).
2. A **Primatio Vault** account with the mobile app installed (iOS / Android).
3. An agent created in the app under **My Agents**:
   - Connection mode: **DPoP (Local / CLI)**
   - Select the credential or folder for your target test site (e.g., `https://practicetestautomation.com/practice-test-login/`).
   - Copy the generated `client_id` (`cli_...`).

## Quick Start

```bash
# 1. Install dependencies
npm install

# 2. (Optional) Install Playwright + Chromium for the browser login step
npm install --no-save playwright
npx playwright install chromium

# 3. Configure environment variables
cp .env.example .env
# Edit .env and set PRIMATIO_CLIENT_ID=cli_...

# 4. Run the demo
npm start
```

Or pass environment variables inline without a `.env` file:

```bash
PRIMATIO_CLIENT_ID=cli_your_agent_id \
PRIMATIO_TARGET_URL=https://practicetestautomation.com/practice-test-login/ \
npm start
```

Set `HEADLESS=false` to watch the browser window open, fill the form, and sign in.

## How the Protocol Flow Works

1. **RFC 8628 Device Grant (`POST /vault/v1/oauth/device`):** Starts linking and prints a short `user_code` (e.g. `5TRN-SGZC`). Approve it in the Primatio Vault mobile app.
2. **Token Exchange (`POST /vault/v1/oauth/token`):** Polls at `>= 8s` intervals until the user approves, returning a DPoP-bound `access_token`.
3. **Discovery (`GET /vault/v1/agent-clients/:clientId/logins`):** Retrieves only non-secret metadata (`item_ref`, `title`, `site`, `username_hint`) for the target URL.
4. **Credential Request & Key Binding (`POST .../credential-requests` & `.../hpke-bind`):** Sends an ephemeral X25519 public key and signs a `vault-hpke-bind+jwt`. Prints the 2-digit `match_code` and triggers a push notification to the Vault app.
5. **Biometric Approval & Consume (`POST .../consume`):** Once approved in the app, consumes the single-use HPKE envelope and decrypts it locally in memory.
6. **Browser Login:** Uses Playwright to fill and submit the login form on `PRIMATIO_TARGET_URL` and verifies the authenticated page.

## Troubleshooting

- **`No authorized login found`:** Make sure the credential is selected in **My Agents** for that `cli_...` and has a valid website URL/domain matching `PRIMATIO_TARGET_URL`.
- **`429 Too Many Requests` on `/oauth/token`:** The token endpoint enforces rate limiting; this script already defaults to an 8-second polling interval.
- **Playwright not installed:** The script still validates OAuth, DPoP, and HPKE decryption without Playwright, and prints the install command for the browser step.
